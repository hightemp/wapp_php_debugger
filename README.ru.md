Логгер-отладчик для PHP-проектов: PHP-библиотека пишет события каждого запроса в JSONL-логи, просмотрщик показывает запросы, сообщения, бэктрейсы и переменные в реальном времени.

> **Статус: стабильная, 1.x.** Просмотрщик написан на Go + Svelte, есть десктоп-версия на Wails; API и формат логов с 1.0 меняются только обратно совместимо (см. [ROADMAP.ru.md](ROADMAP.ru.md)). PHP-библиотека 2.x (PHP 7.4+, формат логов v2) выходит с каждым релизом одним файлом и не опубликована в Packagist; просмотрщик читает и логи библиотеки v1. План, фазы и решения — в [IMPROVEMENT_PLAN.ru.md](IMPROVEMENT_PLAN.ru.md), правила разработки — в [CONTRIBUTING.ru.md](CONTRIBUTING.ru.md).

## Установка одной строкой

```sh
# Просмотрщик (Linux, macOS): сам выбирает сборку под систему, проверяет её и кладёт в /usr/local/bin или ~/.local/bin
curl -fsSL https://github.com/hightemp/wapp_php_debugger/releases/latest/download/install.sh | sh

# PHP-библиотека одним файлом — в корень проекта
curl -fsSLO https://github.com/hightemp/wapp_php_debugger/releases/latest/download/wapp-debugger.php
echo '{"enabled": true, "logs_dir": "tmp/logs"}' > dws_debugger.json
```

Затем две строки в начале запроса — и запуск просмотрщика:

```php
require __DIR__ . '/wapp-debugger.php';
WappDebugger\Debugger::boot(__DIR__ . '/dws_debugger.json');
```

```sh
wapp-debugger serve --logs-dir /var/www/app/tmp/logs   # откройте http://127.0.0.1:8820
```

Однострочники работают с первого опубликованного релиза, где есть эти файлы (v0.2.0). Windows: zip со страницы [Releases](https://github.com/hightemp/wapp_php_debugger/releases). Конкретная версия — `WAPP_DEBUGGER_VERSION=v0.2.0`, другая папка — `WAPP_DEBUGGER_INSTALL_DIR=…` перед `sh`.

## Быстрый старт

1. **Или соберите просмотрщик из исходников** (Go 1.26+, Node 22+):

   ```sh
   make ui-deps build                              # dist/wapp-debugger со встроенным UI
   ```

2. **Подключите библиотеку 2.x к проекту** (PHP 7.4+). Без Composer скопируйте в проект [`client-php/src`](client-php/src), затем как можно раньше в запросе:

   ```php
   require __DIR__ . '/lib/wapp-debugger/autoload.php'; // или vendor/autoload.php от Composer
   WappDebugger\Debugger::boot(__DIR__ . '/dws_debugger.json');
   ```

   и положите `dws_debugger.json` в корень проекта:

   ```json
   {
       "enabled": true,
       "logs_dir": "tmp/logs"
   }
   ```

   Папка логов должна быть доступна PHP на запись. Логирование из кода:

   ```php
   __d(DWS_INFO, 'Заказ создан', ['order' => $order]);
   $total = __log($price) * $quantity; // пишет значение прямо внутри выражения
   __start('db'); /* ... */ __stop('db'); // таймер
   ```

   Ошибки, исключения и фатальные ошибки пишутся сами, секреты маскируются. Laravel, Symfony, WordPress и 1С-Битрикс: [client-php/integrations](client-php/integrations/README.ru.md). PSR-3, Monolog, все настройки и переход с библиотеки v1 — в [client-php/README.ru.md](client-php/README.ru.md). Старые проекты могут остаться на библиотеке v1 ([`client-php/v1/Debugger.class.php`](client-php/v1/Debugger.class.php)): просмотрщик читает обе.

3. **Запустите просмотрщик**:

   ```sh
   dist/wapp-debugger serve                                   # пустым: проекты добавляются в UI
   dist/wapp-debugger serve --logs-dir /var/www/app/tmp/logs  # или сразу с одним локальным проектом
   # откройте http://127.0.0.1:8820
   ```

   `--logs-dir` необязателен. Без него просмотрщик запускается без проектов: они добавляются в UI («Добавить проект») — на этой машине или на SSH- и HTTP-сервере из окна «Серверы» (см. [ниже](#проекты-на-других-серверах)). Проекты хранятся в базе, поэтому при следующих запусках флаги не нужны; повторный запуск с тем же `--logs-dir` дубль не создаёт.

   С `--logs-dir` корень проекта находится по `dws_debugger.json` выше папки логов (иначе это родительская папка); `--root`, `--project` и `--config` задают корень, имя и путь к конфигу явно. Новые и изменившиеся файлы логов импортируются в фоне, новые запросы появляются на странице сами. Переключатель «Отладчик» у проекта меняет `enabled` в `dws_debugger.json` (`bIsOnFlag` в конфиге v1).

   Другие флаги: `--addr` (по умолчанию `127.0.0.1:8820`; другой адрес требует токен), `--token` (лучше `$WAPP_DEBUGGER_TOKEN`, чтобы токена не было в списке процессов), `--db` (база, по умолчанию в папке конфигов пользователя; рядом с ней — `secrets.json` с токенами HTTP-серверов), `--scan-interval` (резервное пересканирование локальных папок, 5 с). Полный список — `wapp-debugger serve --help`.

Интерфейс на английском и русском, темы — светлая, тёмная и высококонтрастная (переключатели в шапке; «Системная» следует цветовой схеме и настройке контраста ОС). **Оформление** в шапке задаёт акцентный цвет поверх любой темы, плотность списков, размер шрифта, шрифт кода (установленный на компьютере) и рамку окна цвета окружения на stage и prod. Там же **редактор тем**: свои цвета поверх встроенной темы с живым предпросмотром и проверкой контраста, обмен темами файлами `.theme.json` («Экспорт», «Импорт»). Настройки хранит просмотрщик, поэтому во всех браузерах и в десктоп-версии они одинаковые. Поиск ищет слова в сообщениях и их контексте или часть URL.

## Проекты на других серверах

Серверы добавляются в окне **«Серверы»** на панели проектов; проект затем кладётся на свой сервер («Добавить проект», выбор сервера). **«Проверить»** у сервера показывает каждый шаг: подключение, папку логов каждого проекта (чтение, запись), конфиг библиотеки и версию PHP.

### SSH

Основной способ: на сервере ничего не нужно открывать и ставить.

- Хост — имя или алиас из `~/.ssh/config`: учитываются `HostName`, `User`, `Port`, `IdentityFile`, `IdentitiesOnly` и цепочки `ProxyJump`. Ключи берутся сначала из `IdentityFile`, затем из ssh-agent (`SSH_AUTH_SOCK`). Пароли и ключи с паролем, не добавленные в агент, пока не поддерживаются.
- Ключи хостов сверяются с `~/.ssh/known_hosts`. Для нового хоста показываются отпечаток и тип ключа с командой, которой его сверить на сервере (`ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub`); подтверждённый ключ пишется в собственный файл просмотрщика, `~/.ssh/known_hosts` не меняется. Изменившийся ключ не принимается.
- Логи читаются по SFTP с опросом раз в 2 секунды; одно подключение на сервер, keepalive и переподключение. Переключатель «Отладчик» переписывает `dws_debugger.json` на сервере за один шаг (временный файл, затем rename) и сохраняет его права. Сервер **«только чтение»** не позволяет ни того, ни удаления логов.
- Логи PHP внутри Docker на этом сервере: укажите в проекте папку volume на хосте.
- Ссылки в IDE для удалённого проекта открывают локальную копию, если она задана («Локальная копия для ссылок в IDE»), иначе — файл на сервере через VS Code (или Cursor) Remote-SSH.

### HTTP-режим библиотеки

Для серверов без доступа по SSH (shared-хостинг). Задайте `http_token` (не короче 32 символов) в `dws_debugger.json` проекта — библиотека начнёт отвечать на свой API, см. [client-php/README.ru.md](client-php/README.ru.md#http-режим), — и добавьте сервер типа **HTTP** с адресом приложения и этим токеном. Используйте `https://`: по обычному `http://` токен и логи идут без шифрования, UI об этом предупреждает. Токен хранится не в базе, а в `secrets.json` рядом с ней, доступном только пользователю, и больше нигде не показывается. Один HTTP-сервер — одно приложение, поэтому на нём один проект; папку логов библиотека знает сама.

### Логи в просмотрщик по HTTP

Для контейнеров, подов и серверов, до которых просмотрщику не дотянуться: логи сами приходят в просмотрщик.

1. Запустите просмотрщик с приёмником: `wapp-debugger serve --ingest-addr 0.0.0.0:8821`. На этом адресе только приёмник (`POST /ingest/v2`, [`spec/ingest.yaml`](spec/ingest.yaml)); интерфейс и его API остаются на `--addr`, на localhost.
2. В настройках проекта нажмите **Создать токен**. Он показывается один раз, вместе с ключами для `dws_debugger.json`:
   ```json
   "push_url": "http://viewer.lan:8821/ingest/v2",
   "push_token": "…"
   ```
   С ними библиотека отправляет события в просмотрщик вместо записи файлов: пачками, раз в секунду в долгом скрипте и остаток в конце запроса. Одна неудачная отправка (таймаут 2 с) выключает запись для этого запроса, так что недоступный просмотрщик не замедлит приложение дважды. Для `https://` нужно расширение `openssl`, как для любого HTTPS в PHP.
3. Или оставьте библиотеку писать файлы и запустите рядом агента: `WAPP_DEBUGGER_PUSH_TOKEN=… wapp-debugger agent --logs-dir /var/www/app/tmp/logs --push http://viewer.lan:8821/ingest/v2`. Он отправляет новые строки по мере записи и повторяет то, что просмотрщик пропустил; после перезапуска отправляет файлы заново, а просмотрщик хранит каждое событие в одном экземпляре.

**Ошибки страниц.** При включённой отправке `<?= \WappDebugger\Debugger::instance()->jsTag() ?>` на странице выводит тег `debugger.js`: необработанные ошибки со стеком, необработанные rejection и `console.error`/`warn` страницы приходят дочерним запросом того PHP-запроса, который её отдал. Токен виден в коде страницы — только для dev и stage. Chrome пускает страницу к приёмнику в локальной сети, если страница в той же сети или открыта по HTTPS.

**Чужие логи.** **Импорт запроса** в панели проекта принимает, кроме экспорта и лог-файлов библиотеки, лог ошибок PHP (`php_errors.log`), лог Laravel (`storage/logs/*.log`) и error log nginx: файл становится одним запросом с его именем, записи — сообщениями с уровнями, файлами, строками и стеками.

### Много серверов сразу

- **Поиск проектов.** **«Найти проекты»** у локального или SSH-сервера обходит указанные папки (до 4 уровней и 5000 папок, без символических ссылок; `vendor`, `node_modules` и `.git` пропускаются) в поисках `dws_debugger.json` и показывает найденное с путями, вычисленными так же, как их вычисляет библиотека; проект добавляется одним нажатием.
- **Проекты по серверам.** Панель проектов группирует проекты по серверам с окружением (`dev`, `stage`, `prod` — своими цветами) и состоянием подключения вживую; имя сервера открывает ленту этого сервера. Общая лента фильтруется по окружению и показывает проект и сервер каждого запроса.
- **Осторожно на stage и prod.** Очистка логов и удаление проекта там требуют ввести имя проекта; переключатель отладчика сначала спрашивает.
- **Часы.** Просмотрщик измеряет, насколько сбиты часы каждого сервера (`date` по SSH, заголовок `Date` в HTTP-режиме), и предупреждает при расхождении больше 2 секунд: иначе порядок запросов разных серверов вводит в заблуждение.
- **Ретеншн.** В настройках проекта задаётся, сколько дней и мегабайт запросов просмотрщик держит в своей базе; старые удаляются раз в 10 минут, файлы логов не трогаются. Импорт идёт не больше чем по 4 проекта сразу и бросает проход через 2 минуты, так что медленный сервер не задерживает остальные.
- **Экспорт и импорт.** **Серверы → «Экспорт / импорт»** выдаёт серверы и проекты в YAML без секретов (токены и ключи хостов остаются в просмотрщике) — хранить в git или передать коллеге; импорт добавляет недостающее и больше ничего не меняет. Токены импортированных HTTP-серверов задаются заново кнопкой **«Токен»**.

## Десктоп-версия

Тот же просмотрщик в окне, без сетевого порта. Установщики приложены к каждому [релизу](https://github.com/hightemp/wapp_php_debugger/releases):

| Система | Файл | Примечания |
|---|---|---|
| Linux | `.deb`, `.AppImage`, `.tar.gz` | `.deb` нужны `libgtk-4-1` и `libwebkitgtk-6.0-4` (Ubuntu 24.04, Debian 13); AppImage везёт библиотеки с собой |
| Windows | `_setup.exe`, `.zip` | ставится для текущего пользователя, без прав администратора; нужен WebView2 (в Windows 11 он есть) |
| macOS | `.dmg`, `.tar.gz` | одно приложение для Apple silicon и Intel, macOS 11+ |

**Первый запуск.** Приложения пока не подписаны (п. 10.28 плана), поэтому система один раз спросит:

- macOS: правый клик по приложению → **Открыть** → **Открыть**; или `xattr -dr com.apple.quarantine /Applications/wapp-debugger.app`;
- Windows: SmartScreen → **Подробнее** → **Выполнить в любом случае**;
- Linux: `sudo apt install ./wapp-debugger-desktop_*.deb` или `chmod +x` для AppImage.

Что десктоп добавляет к браузерной версии (**«Настройки»** в шапке):

- значок в трее (в строке меню на macOS) с числом новых запросов с ошибками и меню последних; закрытое окно оставляет приложение там;
- системные уведомления о новых запросах с ошибками — или и с предупреждениями — во всех или выбранных проектах; всплеск приходит одним уведомлением; клик открывает запрос;
- ссылки `wapp-debugger://open?project=3&request=42&message=1001` открывают запрос в приложении (из чата, задачи, скрипта); установщики регистрируют схему, повторный запуск передаёт ссылку уже открытому окну;
- запуск при входе в систему; окно открывается там, где было;
- сообщение в шапке о новой версии (GitHub Releases раз в сутки; отключается).

Из исходников: `make desktop-build` (нужен компилятор C, а в Linux ещё GTK4 + WebKitGTK 6.0; `make desktop-deps` проверяет их и подсказывает, как поставить недостающее в вашей системе), затем `dist/wapp-debugger-desktop [--logs-dir …]`; `--logs-dir` и здесь необязателен. `make desktop-package` собирает установщики текущей системы; подробнее — в [desktop/README.ru.md](desktop/README.ru.md).

## Docker

```sh
docker run -d --name wapp-debugger -e WAPP_DEBUGGER_TOKEN=<token> -p 127.0.0.1:8820:8820 \
  --user "$(id -u):$(id -g)" -v /var/www/app:/var/www/app -v wapp-debugger:/data \
  ghcr.io/hightemp/wapp-debugger --logs-dir /var/www/app/tmp/logs
# откройте http://127.0.0.1:8820/?token=<token>
```

В контейнере просмотрщик слушает все интерфейсы, поэтому токен обязателен. Монтируйте проект по тому же пути, что и на хосте: тогда пути в просмотрщике и ссылки в IDE совпадут. `--user` нужен, чтобы читать логи и переключать отладчик в `dws_debugger.json`. Локально образ собирается `make docker-build`.

## Доступ по сети

По умолчанию просмотрщик отвечает только на `127.0.0.1` и только на loopback-имена хоста — это заодно защищает от DNS rebinding. Чтобы открыть его другим машинам, задайте токен; без токена просмотрщик откажется слушать не-loopback адрес:

```sh
WAPP_DEBUGGER_TOKEN=$(openssl rand -hex 32) dist/wapp-debugger serve --addr 0.0.0.0:8820 --logs-dir …
# один раз откройте http://<host>:8820/?token=<token>: токен переедет в HttpOnly-cookie
# API-клиенты передают Authorization: Bearer <token>
```

Переменная окружения лучше `--token`: её не видно в списке процессов. Просмотрщик ставит строгий Content-Security-Policy, отклоняет запись с чужих origin и ограничивает тело запроса 1 МиБ. TLS он не терминирует: через недоверенные сети используйте TLS-прокси или SSH-туннель.

У самой библиотеки HTTP-команд по умолчанию нет (`?debug_msg=…` требует константу `DA_HTTP_TOKEN` и заголовок `X-Debugger-Token`); новый просмотрщик их не использует.

## Структура

| Каталог | Что |
|---|---|
| `server/` | Просмотрщик на Go: `wapp-debugger serve`, API, живые обновления, встроенный UI |
| `ui/` | Веб-интерфейс на Svelte, английский и русский |
| `server/cmd/wapp-debugger-desktop/` | Десктоп-версия на Wails v3 |
| `client-php/` | PHP-библиотека 2.x; в `v1/` — библиотека v1 для старых проектов |
| `spec/` | Форматы логов, контракты API и фикстуры |

С версии 1.0 формат логов v2 и API (`/api/v1`, приёмник логов по HTTP, HTTP-режим библиотеки) меняются только обратно совместимо: библиотека или скрипт, написанные под 1.0, работают с любым просмотрщиком 1.x ([spec/frozen](spec/frozen/README.ru.md)). У релизов есть контрольные суммы, SBOM и подтверждение происхождения сборки (`gh attestation verify <файл> --repo hightemp/wapp_php_debugger`); о проблемах безопасности — приватным сообщением ([SECURITY.ru.md](SECURITY.ru.md)).

Старого PHP-просмотрщика на EasyUI больше нет; он остался в истории git (тег `legacy-hotfix` — его последняя версия).
