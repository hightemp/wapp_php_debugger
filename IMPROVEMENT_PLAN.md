## 0. Текущее состояние (кратко)

Проект состоит из двух частей:

1. **Клиентская библиотека** — `Debugger.class.php`. Подключается в отлаживаемый проект, пишет по одному JSONL-файлу на запрос: первая строка — заголовок фиксированной длины (1000 байт, перезаписывается при завершении), дальше строки сообщений (`sType`, `sMessage`, `oVars`, `oBackTrace`, `aBackTrace`, `iTimestamp`). Ещё она принимает управляющие команды через GET-параметр `debug_msg*` (`status`, `start`, `stop`, `set_config`, `clear`, `info`, `get_file`).
2. **Веб-приложение просмотра**: `index.php` + `ajax.php` + `controllers/*` + jQuery EasyUI + RedBeanPHP/SQLite. Оно сканирует папку логов проекта, импортирует файлы в SQLite (`tdebugfiles`, `tdebugmessages`) и показывает три панели: проекты → файлы (запросы) → сообщения → детали (бэктрейс и дерево переменных).

Идея хорошая и рабочая, но в коде много мест, где всё ломается из коробки, есть серьёзные дыры в безопасности и остался мёртвый код из другого проекта (links/categories/groups/notes/tables).

## 1. Критичные баги (приложение не работает или падает)

### 1.1 PHP-библиотека `Debugger.class.php`

> Библиотека уже подключена в рабочие проекты, поэтому пункты с 🔥 правятся прямо в текущем файле (это дешёвые правки, которые убирают фатальные ошибки). Остальное ↪ решается переписыванием библиотеки и форматом v2 (п. 4.1, 4.2): чинить это в старом коде — двойная работа.

- [x] 🔥 **`DA_FLAG` и `DA_ROOT_DIR` не определены** (строки 11–16 закомментированы). В PHP 8 обращение к неопределённой константе — это фатальный `Error`, поэтому `__d()`, `__log()`, `__start()` и `__stop()` падают сразу после подключения файла. Нужно определять их по умолчанию (`defined() || define()`) или заменить на свойства конфига.
- ↪ **`fnGetDirSize()`** (стр. 133): `"\1"` в двойных кавычках — это символ `chr(1)`, а не обратная ссылка. Функция всегда возвращает мусор, поэтому `iLogsSizeLimit` не работает. Надо `'$1'` или, лучше, считать размер на PHP без `du`.
- [x] 🔥 **`save_debug_message`** (стр. 225): `json_decode($_POST['sData'])` возвращает объект, а дальше к нему обращаются как к массиву (фатальная ошибка). Кроме того, аргументы передаются не в том порядке: `sLang` попадает в параметр `$sURL`.
- [x] 🔥 **`fastcgi_finish_request()`** (стр. 376) вызывается без `function_exists()`. Под Apache mod_php или `php -S` это фатальная ошибка в shutdown-функции.
- [x] 🔥 (минимально: обрезать заголовок до 1000 байт, без `ValueError`) ↪ (полностью: формат v2 без перезаписываемого заголовка) **Заголовок фиксированной длины 1000 байт** (`fnPrintJSONLineWithLength`, стр. 506). Если URL или `argv` длинные, заголовок оказывается длиннее 1000 байт, `fnUpdateHeader()` перезаписывает начало первых сообщений, и файл портится. При этом `str_repeat` с отрицательным числом бросает `ValueError`.
- [x] 🔥 **`iArraySizeLimit`**: `count($aVar, COUNT_RECURSIVE)` на скаляре бросает `TypeError` в PHP 8.
- ↪ **`fnGetSysUser()`** (стр. 159) жёстко завязан на `$_SESSION['USER_INFO']['login']` конкретного проекта. Нужен callback-резолвер пользователя в конфиге.
- [x] 🔥 `posix_getpwuid` и `session_id()` вызывать только при наличии расширения или активной сессии.
- ↪ `sleep(1)` в цикле при совпадении имени файла (стр. ~640) тормозит запрос на секунду. Имя файла нужно делать уникальным: `msTimestamp-pid-random`.
- ↪ Обработчик ошибок логирует только `E_USER_ERROR`: warnings, notices и deprecated теряются, предыдущий обработчик не вызывается. `set_exception_handler` нет совсем, поэтому неперехваченные исключения не попадают в лог.
- ↪ Запись без `flock()`: при `fastcgi_finish_request` и параллельных sub-запросах строки могут перемешаться.

### 1.2 Сервер просмотра

> ↪ **В текущем PHP-сервере не чиним**: он удаляется целиком после MVP Go-версии (п. 8, фаза 5). Список нужен как набор требований и тест-кейсов для Go-реализации (п. 7.3): каждый пункт — сценарий, который новый сервер должен обрабатывать правильно.

- ↪ **`lib.php` содержит код другого проекта**: `T_CATEGORIES`, `T_LINKS` и `fnBuildRecursive*Links*` не определены, поэтому `delete_project` → `fnBuildRecursiveProjectsTreeDelete()` падает. То же в `update_/create_debug_file` и `update_/create_debug_message`: там `T_GROUPS`, `tgroups`, `tdebug_files`.
- ↪ **`scan_debug_files`** (`controllers/debug_files.php:12`): «последний файл» ищется по всем проектам, а не по текущему, поэтому при нескольких проектах файлы пропускаются. Сравнение `file_name >` строковое.
- ↪ Импорт читает заголовок через `fread($h, 1000)` (стр. 43) и не проверяет, валиден ли JSON. Весь файл загружается в память (`file_get_contents` + `explode`), и каждое сообщение сохраняется через два `R::store`. На файлах по 50+ МБ это падает по памяти и работает очень медленно.
- ↪ `count_errors` всегда равен `0`.
- ↪ `controllers/tags.php` не подключён в `ajax.php`; внутри невалидный SQL (`DELETE ? WHERE ...`, переменные-переменные `${$aRequest[...]}`).
- ↪ `database.php:24`: настройки MySQL захардкожены и игнорируют `config.json`.
- ↪ `index.php` подключает несуществующие или ненужные скрипты (`speadsheet.js`, `all.js`, `easymde`), а `highlight.js` берётся с CDN без версии (`latest`).
- ↪ `sse.php` на самом деле не стримит: отдаёт одно событие и закрывается, EventSource переподключается примерно каждые 3 с, и каждый раз выполняется `glob()` по папке. По факту это скрытый поллинг.
- ↪ `config.php:3` — `error_reporting(E_ERROR | E_PARSE)` скрывает все предупреждения, из-за этого описанные выше баги не видны.

## 2. Безопасность

Отладчик работает на машине разработчика, но клиентская часть встраивается в **проект**, который может оказаться на стейдже или в проде. Поэтому это важно.

### 2.1 PHP-библиотека

- [x] 🔥 **Управление через GET без авторизации.** Любой посетитель сайта может вызвать `?debug_msg=start`, `stop`, `clear` или `set_config`. Hotfix: управляющий API **выключен** по умолчанию; включается константой `DA_HTTP_TOKEN`, и тогда каждый запрос обязан передать этот токен (сравнение через `hash_equals`). Полноценный опциональный HTTP-режим делается в новой библиотеке (п. 4.1), основной способ управления — конфиг-файл по SSH (п. 7.4).
- [x] 🔥 **Чтение произвольных файлов**: `?debug_msg=get_file&file=../../../etc/passwd` (стр. 320). Нужен `realpath()` и проверка, что путь лежит внутри `sProjectRootPath`.
- [x] 🔥 **Command injection**: `set_config` записывает пути из `$_POST`, которые потом подставляются в `exec("rm -rf ...")`, `du -s`, `df -h` и `ls ... | xargs rm` (стр. 206, 284). Нужно убрать `exec` полностью и перейти на `glob`/`unlink`/`RecursiveDirectoryIterator`.
- [x] 🔥 **Утечка секретов**: при подключении автоматически логируются `$_SERVER`, `$_SESSION`, `$_COOKIE` и `$_POST`, то есть пароли, токены, ключи из env. Нужна маскировка по списку ключей (`password`, `token`, `secret`, `authorization`, `cookie`, `api_key`…) с возможностью настройки, а автодамп суперглобалов должен включаться опцией.
- ↪ Права `0777` и `0666` на логи и конфиг заменить на настраиваемые (по умолчанию `0775`/`0664`). ✅ *Сделано в библиотеке 2.x: `file_mode`/`dir_mode` (фаза 6).*
- ↪ Защита от включения в проде: опция `allowed_envs` или проверка `APP_ENV`.

### 2.2 Сервер просмотра

> Текущий сервер работает до MVP Go-версии, поэтому в нём закрываем только то, что эксплуатируется извне без усилий (🔥: XSS, CORS, прослушивание всех интерфейсов). Остальное ↪ — требования к Go-серверу.

- ↪ **SQL-инъекции**: `fnGenerateFilterRules()` (`lib.php:53`) подставляет `field` и `value` из запроса прямо в SQL; `fnPagination()` (`lib.php:63`) делает то же с `page` и `rows`. Нужно: whitelist полей, `?`-биндинги, `(int)` для пагинации.
- ↪ **Command injection**: `exec("rm -rf {$sDLP}/{$oDebugFile->file_name}")` (`controllers/debug_files.php:136, 186`).
- [x] 🔥 **XSS**: `s_message` выводится как сырой HTML (`static/app/modules/debug_messages.js:238`, `debug_message_info.js:59`). Сообщения содержат пользовательский ввод (`$_GET`, `$_POST`), поэтому открытие лога может выполнить чужой JS. Нужно экранировать на фронте, а ссылки на файлы строить уже из экранированного текста.
- [x] 🔥 **CSRF + CORS** (hotfix: убрать `*`; полноценно ↪ в Go): nginx отдаёт `Access-Control-Allow-Origin: *` (`docker/nginx/conf.d/vhost.conf:48`), а деструктивные методы (`clear_files_debug_files`, `delete_*`) доступны через GET. Любая открытая вкладка может стереть логи. Нужно: убрать `*`, разрешить мутации только через POST, добавить CSRF-токен или проверку `Origin`.
- [x] 🔥 Слушать `127.0.0.1`, а не `0.0.0.0` (`bin_start_server.sh`, порт nginx в `docker-compose.yaml`). ↪ Авторизация — в Go (п. 7.3).

## 4. Архитектура

### 4.1 PHP-библиотека как отдельный Composer-пакет

Сейчас клиент приходится копировать в проект и править пути прямо в файле. Предлагается:

- [x] Вынести библиотеку в `client-php/` монорепо (п. 3), namespace `WappDebugger\`, PSR-4. ✅ **Минимальная версия PHP 7.4** (п. 10.13). Следствия:
  - нельзя: `enum`, `match`, union-типы, `mixed`, nullsafe `?->`, named arguments, constructor promotion, `readonly`, атрибуты, `str_contains`/`str_starts_with` (без полифилла);
  - можно: типизированные свойства, стрелочные функции, `??=`, spread в массивах;
  - уровни логов — класс с константами (`Level::ERROR`), а не enum;
  - PHPStan с `phpVersion: 70400`, PHPUnit 9.6 (работает на 7.4–8.x), PHP-CS-Fixer с правилами под 7.4;
  - CI гоняет тесты на 7.4 и на всех версиях 8.x, чтобы не было deprecation-предупреждений на новых PHP.
- [x] Разделить ответственности: — *фаза 6; `Writer` без интерфейса — выключенный `Debugger` вместо `NullWriter`, пик памяти и длительность — в `request_end` без отдельного `Profiler`; `HttpWriter` — фаза 10.*
  - `Config` — загрузка из массива, env или JSON, значения по умолчанию;
  - `Writer` (интерфейс) → `JsonlFileWriter`, `NullWriter`; `HttpWriter` (push на сервер) — позже, когда в Go появится HTTP-приёмник (фаза 10);
  - `Serializer` — безопасная сериализация переменных: лимиты глубины, длины строк и количества элементов, объекты (класс + свойства, включая private), рекурсия, ресурсы, замыкания, исключения;
  - `Masker` — маскировка секретов;
  - `ErrorHandler` — ошибки, исключения, фатальные ошибки в shutdown;
  - `Timer` и `Profiler` — таймеры, память (`memory_get_peak_usage`), длительность запроса;
  - `HttpEndpoint` — ✅ **опциональный HTTP-режим для легаси-окружений без SSH** (п. 10.22). По умолчанию выключен и при отсутствии токена не включается вовсе. Обязательный токен (≥ 32 символа, `hash_equals`, только в заголовке `X-Debugger-Token`), опциональный allowlist IP, ограничение частоты. Команды: `status`, `enable`/`disable`, `list` (список файлов логов), `read` (чтение файла с offset), `clear` (только внутри папки логов). Нет `get_file` и `set_config` с путями: исходники и конфиг доступны только по SSH. Ответы в JSON, формат описан в OpenAPI (`spec/`). Основной способ управления — запись конфига по SSH (п. 7.4).
- [x] Не делать работу при подключении: никакого `du`, `df` и чтения конфига на каждый запрос, если отладчик выключен. Проверка флага должна стоить ровно один `is_file()` или чтение константы.
- [x] Совместимость: оставить глобальные `__d()`, `__log()`, `__start()`, `__stop()` как тонкие обёртки (обратная совместимость), добавить `Debugger::log()`/`info()`/`warning()`/`error()`.
- [x] **PSR-3 адаптер** (`Psr\Log\LoggerInterface`) и **Monolog Handler**, чтобы подключаться к Laravel, Symfony и любым проектам с Monolog без правок кода. Из-за PHP 7.4 нужно поддержать две линии зависимостей: `psr/log` 1.x (PHP 7.4) и 2.x/3.x (PHP 8, другие сигнатуры), Monolog 2 (массив) и Monolog 3 (`LogRecord`, PHP 8.1+). Нужный адаптер выбирается при загрузке; все комбинации покрыты CI-матрицей.
- [ ] Хелперы для частых сценариев: логирование SQL (обёртка над PDO / событие ORM) с длительностью, логирование HTTP-запросов (Guzzle middleware).
- [x] **Сборка в один файл** (запрос владельца): `client-php` упаковывается в один `wapp-debugger.php` (все классы и глобальные функции, без автозагрузчика) для подключения одним `require` в проектах без Composer; файл собирается `make`, проверяется теми же тестами и прикладывается к каждому релизу (фаза 7, шаг 1).

**Правила:**

| Слой | Стиль | Пример было → стало |

## 6. Новый веб-интерфейс на Svelte

> Здесь «клиент» — это веб-интерфейс просмотра логов (сейчас `index.php` + `includes/layout.php` + `static/app/modules/*.js` на jQuery EasyUI). PHP-библиотека `Debugger.class.php` к этому этапу отношения не имеет.

> ✅ **Решено:** UI пишется **с нуля** на Svelte 5 + Vite. Из старого интерфейса не переносится ни код, ни разметка, ни стили, ни иконки. Он используется только как список функций, которые должны остаться (п. 6.6). EasyUI, jQuery и всё содержимое `static/app` удаляются.

### 6.1 Почему переписывать

- EasyUI устарел, тянет jQuery и ограничивает UI: treegrid переменных ломается по стилям (см. комментарий в `includes/layout.php`), раскладка жёстко задана пикселями (`width:540px`, `440px`).

- Нет виртуализации: таблица на 10k+ сообщений тормозит, поэтому пагинация обязательна.
- Разметка, состояние и запросы перемешаны, тестов нет.

### 6.2 Стек

- [x] ✅ **Svelte 5** (runes) + **TypeScript** + **Vite**, SPA без SSR и без SvelteKit. Маршрутизация — лёгкий клиентский роутер (hash или History API с fallback на `index.html` в Go-сервере).
- [x] Сборка в статические файлы, которые встраиваются в Go-бинарник (`embed.FS`, см. п. 7).

## 7. Бэкенд просмотрщика на Go

> ✅ **Решено.** На Go переписывается **сервер просмотра** (`index.php`, `ajax.php`, `controllers/*`, `sse.php`, `bin.php`, RedBean/SQLite). **Отладчик `Debugger.class.php` остаётся на PHP**: он работает внутри отлаживаемого PHP-проекта.

### 7.1 Что даёт Go

- **Один бинарник** `wapp-debugger` со встроенным Svelte-UI (`embed.FS`): не нужны PHP-FPM, nginx и Docker с 15 расширениями. Запуск: `wapp-debugger serve --projects ./projects`.
- **Фоновые процессы**: наблюдение за папками логов через `fsnotify`, инкрементальный импорт растущих файлов и настоящий SSE/WebSocket. В PHP-FPM долгоживущие соединения держат воркеры, в Go это дёшево.
- **Скорость и память**: потоковый разбор JSONL по гигабайтным логам, батчевые вставки, параллельный импорт нескольких проектов.
- **Приём логов по HTTP/UDP** (п. 5.2) реализуется естественно, без общей файловой системы.
- Кроссплатформенные сборки через goreleaser (Linux/macOS/Windows) и маленький Docker-образ (distroless/scratch).
- Десктоп-приложение на Wails из того же Go-ядра и того же Svelte-UI (п. 7.8).

### 7.2 Минусы и риски

- Второй язык в проекте: библиотека остаётся на PHP, сервер становится на Go. Порог входа для контрибьюторов-PHP-разработчиков выше.
- Работы в PHP-сервере и старом UI будут выброшены, поэтому их развитие **замораживается**. Исправляются только критичные баги и дыры безопасности (п. 1.2, 2.2), пока Go-сервер и новый UI не готовы. После этого PHP-сервер и EasyUI удаляются одновременно.
- Нужно аккуратно перенести логику маппинга путей Docker ↔ хост (`path`, `global_path`, `relative_path`, `lib.php:fnGetProject*Path`) и ссылок в редактор.

### 7.4a Легаси HTTP-режим (опционально)

Для серверов, куда нет SSH-доступа (старый shared-хостинг, чужая инфраструктура), просмотрщик может работать через HTTP-режим PHP-библиотеки (п. 4.1).

- [x] Тип сервера `http`: базовый URL проекта + токен (хранится в системном хранилище секретов, как SSH-пароли, п. 10.19). — *фаза 7: до системного хранилища (п. 10.19) токен лежит в `secrets.json` рядом с базой (права 0600), в API только на запись; один сервер — одно приложение и один проект.*
- [x] `HTTPPullSource`: опрос `list` и `read` с offset по расписанию, live tail — частым опросом; `enable`/`disable`/`clear` из UI. — *фаза 7: `source.HTTP`, опрос раз в 2 с; проходит общий контракт `sourcetest` и тест против настоящей библиотеки под `php -S`.*
- [x] Только HTTPS (HTTP — с явным предупреждением в UI), проверка сертификата, таймауты, ограничение частоты запросов со стороны просмотрщика. — *фаза 7: сертификат проверяется всегда, таймаут 30 с, запросы не чаще раза в 50 мс, после 429 — пауза по `Retry-After`; `http://` — предупреждение в форме и в проверке.*

- ✅ Старый HTTP API (`?debug_msg=…`) просмотрщик не поддерживает (п. 10.36): для HTTP-режима на сервере ставится библиотека 2.x.

## 8. Порядок работ: фазы и вехи

### 8.1 Что было не так в предыдущей версии порядка

1. **Работа впустую по коду, который будет удалён.** Этапы 1–4 включали починку и оптимизацию старого PHP-сервера и EasyUI (RedBean, индексы, импорт, теги, мёртвый код, Dockerfile), хотя оба удаляются. Теперь в старом коде только hotfix (🔥), остальное ↪ — требования к Go.
2. **Двойная работа в PHP-библиотеке.** Баги чинились в старом файле, а потом тот же код переписывался. Теперь в старом файле только дешёвые правки фатальных ошибок и уязвимостей.
3. **HTTP-управление строилось дважды** (токены в старом коде и в новом). Теперь в hotfix — только «выключено по умолчанию + обязательный токен», а полноценный опциональный HTTP-режим делается один раз в новой библиотеке.
4. **Схема для нескольких серверов шла последней (7в)**, хотя она определяет БД и API. Теперь схема проектируется в фазе 3 вместе с контрактами.
5. **Главные технические риски проверялись в конце**: встраивание UI в Go, SSE внутри Wails (п. 10.27), сборка на трёх ОС, CGO/WebKit на Linux. Теперь их снимает walking skeleton в фазе 4.
6. **Нет вех и MVP.** Релизный workflow стоял после всего, первый релиз — неизвестно когда. Теперь у каждой фазы есть версия.
7. **Монорепо не было отдельным шагом**, хотя от него зависят Makefile и CI; в п. 4.1 было `packages/client`, в остальных местах `client-php/`.
8. **Параллельность «Go и UI одновременно»** реальна только при двух исполнителях. ✅ Исполнитель один (п. 10.34), поэтому фазы идут последовательно, MVP — вертикальными срезами, а PHP-библиотека v2 перенесена после MVP.

Найдено и исправлено по ходу:

- Непойманное исключение нельзя пробросить из обработчика: PHP 8 снова вызывает тот же обработчик, и он уходил в бесконечную рекурсию. Теперь вывод PHP воспроизводится байт в байт (с учётом `log_errors`, `display_errors`, `html_errors`), код выхода 255.
- После нехватки памяти обработчик выставлял лимит «текущее потребление + 16 МБ» и мог его понизить; теперь лимит только повышается.
- Переключатель отладчика в просмотрщике менял `bIsOnFlag`, даже когда в конфиге есть `enabled`, которое слушает библиотека 2.x; теперь `enabled` важнее, как в библиотеке.
- Прежний `make php74-test` гонял PHP 7.4 на `vendor/`, собранном для 8.4; теперь зависимости ставятся под 7.4 в копии, через прокси хоста.

Решения по ходу:

- Суперглобальные массивы при старте — `$_GET`, `$_POST`, `$_FILES`; `$_SERVER`, сессия и cookie — только через `log_globals` (п. 2.1).
- Ошибки вне `error_reporting` и подавленные `@` не пишутся — как и у самого PHP.
- Права в `dws_debugger.json` — восьмеричные строки (`"0664"`): в JSON нет восьмеричных чисел.
- HTTP-режим отдаёт и удаляет только файлы с именами логов — строже контракта, где запрещён лишь `/`.
- PHPStan не анализирует обработчики Monolog: с `phpVersion` 7.4 он не видит классов Monolog 3, а Monolog 2 и 3 нельзя проверить одним запуском; их покрывают тесты на обеих линиях.

Осталось для 2.0.0: репозиторий `hightemp/wapp-php-debugger`, deploy key в environment `release`, регистрация в Packagist; затем `Debugger::VERSION = '2.0.0'` и тег `client-php/v2.0.0`.

- **Проверки**: SSH-сервер внутри Go-тестов (sftp, exec, jump, keepalive, обрыв); `make ssh-e2e` — весь путь пользователя против настоящего OpenSSH в Docker, в CI тоже; HTTP-источник — общий контракт на тестовом сервере и тест против настоящей библиотеки под `php -S`.

Найдено при проверке на настоящем OpenSSH и исправлено:

- С большим числом ключей в ssh-agent сервер обрывал вход («Too many authentication failures»): ключ из `IdentityFile` предлагался последним. Теперь первым, как в OpenSSH, и учитывается `IdentitiesOnly`.
- Запрашивался не тот тип ключа хоста: подсказка в UI отправляла сверять ED25519 при ECDSA-ключе, а ключ другого типа в `known_hosts` выглядел как «ключ изменился». Теперь сначала запрашиваются известные типы, для новых хостов — ED25519, и UI называет тип и файл.
- Escape и Tab в окнах не работали, когда фокус уходил с исчезнувшей кнопки; теперь — стек окон и обработка на `window`.
- Без `--logs-dir` не было локального сервера, и сохранение локального проекта молча не срабатывало.

Решения по ходу:

- Опрос SFTP раз в 2 с (п. 10.18), только ssh-agent и ключи (п. 10.19), Docker — через путь volume на хосте (п. 10.21).
- Токен HTTP-сервера до системного хранилища секретов (п. 10.19) — в `secrets.json` (0600) рядом с базой; в базе и в ответах API его нет.
- HTTP-сервер — одно приложение и один проект: у библиотеки одна папка логов; голый 404 без `problem+json` — «библиотека не ответила» (неверный адрес или токен), а не «файла нет».
- Необязательные шаги проверки (конфиг библиотеки, PHP, HTTPS) — предупреждения: без конфига отладчик просто выключен, `exec` может быть запрещён.

Осталось на потом: ввод пароля ключа и пароли SSH через системное хранилище (п. 10.19), `inotifywait` вместо опроса, сжатие и лимит скорости SSH, превью исходников по SFTP.


- Каждая веха — тег и релиз через `release.yml` (с фазы 5), чтобы новой версией можно было пользоваться сразу, не дожидаясь v1.0.

- ↪ Маскируются только ключи массивов: секреты внутри объектов, в тексте сообщений и в query-строке `sURL` не маскируются (п. 4.1, `Masker`).

**Старый сервер просмотра:**

- [x] `s_message` экранируется на сервере (`controllers/debug_messages.php`) до вставки ссылок на файлы; во всех formatter-ах и колонках EasyUI (`debug_files.js`, `debug_messages.js`, `debug_message_info.js`, `projects.js`) данные из логов экранируются через `fnEscapeHtml`/`fnEscapeFormatter` (`static/app/modules/lib.js`), включая URL запроса, бэктрейс и дерево переменных.

- [x] Слушать только `127.0.0.1`: `bin_start_server.sh`, проброс порта в `docker-compose.yaml`, пример в README.

**Проверка:** набор сценариев на PHP 7.4 (Docker `php:7.4-cli`) и 8.4: без конфига, логирование с секретами и URL на 1500 символов, HTTP без токена, с неверным и коротким токеном, с верным токеном (`status`, `get_file` с `../`, `set_config` с путями, `clear` с символической ссылкой, `debug_msg=../…`), очистка по лимиту, реальный веб-запрос через `php -S`.
