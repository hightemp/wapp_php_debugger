# Замороженные контракты

[English](README.md) · **Русский**

В 1.0 заморожены контракты, через которые общаются части wapp-debugger: дальше они меняются только
обратно совместимо, поэтому библиотека, агент или скрипт, написанные под 1.0, продолжают работать
с любым просмотрщиком 1.x.

`v1.0/` — копия контрактов в том виде, в каком они были в 1.0. Она никогда не правится.

| Контракт | Замороженная копия | Чем проверяется |
|---|---|---|
| API просмотрщика v1 (`/api/v1`) | [`v1.0/openapi.yaml`](v1.0/openapi.yaml) | `make spec-compat` (oasdiff: ни ломающих изменений, ни предупреждений) |
| Приёмник отправленных логов (`/ingest/v2`) | [`v1.0/ingest.yaml`](v1.0/ingest.yaml) | `make spec-compat` |
| HTTP-режим библиотеки 2.x | [`v1.0/library-http.yaml`](v1.0/library-http.yaml) | `make spec-compat` |
| Формат логов v2 | [`v1.0/logformat/`](v1.0/logformat/event.schema.json), [`v1.0/fixtures/`](v1.0/fixtures) | `server/internal/spec/frozen_test.go`: каждый замороженный лог проходит текущую схему и читается просмотрщиком без проблем |

## Что можно менять

- Новые эндпоинты, новые необязательные параметры запроса и поля запросов, новые поля ответов.
- Новые поля и типы событий в формате логов v2 (незнакомые поля просмотрщик пропускает), новые
  значения перечислений там, где читателям сказано их ожидать.
- Описания, примеры, лимиты, которые только расширяются.

## Что нельзя

- Удалять или переименовывать эндпоинт, поле, значение перечисления или тип события; делать
  необязательное обязательным; сужать тип или лимит; менять смысл поля.

Такое изменение ждёт новой мажорной версии: API v2 в `/api/v2` рядом с v1, формат логов v3 с
`"v": 3` рядом с v2. Новая замороженная копия тогда ляжет в `v2.0/`.
